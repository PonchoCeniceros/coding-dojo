# 3.1 · Stack y heap

---
layout: center
---

## El Stack
El Stack es una estructura de datos de acceso ultra rápido. Funciona bajo la regla de que lo último en llegar es lo primero en salir. El compilador solo permite guardar aquí datos cuyo tamaño exacto se conoce desde el momento en que se escribe el código.

<br>

* **¿Cómo funciona?**: Al llamar a una función, sus variables se "apilan" una arriba de otra en memoria. Al terminar la función, todo ese bloque se limpia instantáneamente.

<br>

* **Tipos que viven aquí**: los literales numéricos y booleanos, los caracteres (`char`), y las colecciones de tamaño fijo (arreglos `[T; N]` y tuplas) mientras su contenido también sea de tamaño fijo.

---
layout: center
---

* **Comportamiento al asignar**: con estos tipos, `let y = x;` deja **las dos variables vivas** e independientes.

```rust
let x = 42;                     // vive en el stack
let y = x;                      // ambas quedan usables
println!("x: {x}, y: {y}");
```

<br>

Por qué ocurre eso, y por qué no siempre ocurre, es la pregunta de 3.2 Ownership.

## El Heap
El Heap se utiliza para datos más complejos cuyo tamaño es dinámico, desconocido al compilar, o que necesitan crecer y cambiar durante la ejecución del programa.

<br>

* **¿Cómo funciona?**: el asignador de memoria (*allocator*) del programa busca un espacio libre en el Heap, guarda los datos ahí y genera un **apuntador** (una variable con la dirección de esa ubicación). El apuntador (que mide siempre lo mismo) se guarda en el Stack para acceso rápido, pero el contenido real está en el Heap.

<br>

* **Tipos que viven aquí**: Estructuras dinámicas como `String` o listas que pueden crecer.

---
layout: center
---

* **Comportamiento**: A diferencia del Stack, los datos que se guardan en el Heap **no se duplican de forma automática**. Rust implementa una regla estricta de propiedad para evitar accidentes en la memoria. Al asignar una variable del Heap a otra (ej. `let s2 = s1;`), Rust no duplica el contenido del Heap; solo copia el puntero en el Stack e **invalida** la variable original (`s1`): el dato sigue vivo, pero `s1` deja de ser su dueña.

<br>

* **Resultado**: La propiedad del dato se **mueve** a la nueva variable. La variable vieja queda totalmente inválida para proteger el programa.

```rust
let s1 = String::from("hola"); // Datos en el Heap
let s2 = s1; // La propiedad se mueve a s2. s1 queda inválida.

// println!("{}", s1);
// ❌ ERROR de compilación: No puedes usar s1 porque su valor se movió.
```

## El primer tipo del heap

`String` es el tipo de texto que crece, y por eso vive en el heap. Es el que sostiene
todos los ejemplos de ownership y borrowing de esta sección.

```rust
fn main() {
    let s = String::from("hola");   // el contenido vive en el heap
    println!("{s}");
}
```

Su contraparte prestada, `&str`, y la diferencia completa entre las dos, llegan en
3.4, en cuanto exista el préstamo.
