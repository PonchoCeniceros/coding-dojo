# 7.4 · Manejo de errores idiomático

---
layout: center
---

## El problema: cada operación falla distinto

`?` (5.2 Result) propaga el error, pero la firma tiene que declarar **un** tipo de error. En
cuanto una función combina dos operaciones que fallan distinto —leer un archivo y
convertir un número— no hay un `E` obvio que poner.

<div class="important-note">

Las tres respuestas, de menos a más ceremonia: `Box<dyn Error>`, un enum propio, o un
enum propio generado con una librería.

</div>

layout: center
---

## `Box<dyn Error>`: la brocha gorda

```rust
use std::error::Error;

fn sumar(a: &str, b: &str) -> Result<i32, Box<dyn Error>> {
    let x: i32 = a.parse()?;   // ParseIntError
    let y: i32 = b.parse()?;
    Ok(x + y)
}
```

* Cualquier error que implemente `Error` se convierte solo a `Box<dyn Error>`.
* Es despacho dinámico (6.3 Despacho dinámico): un puntero a "algo que sabe ser un error".
* A cambio, quien llama pierde la capacidad de distinguir **qué** falló.

## Un enum de error propio

```rust
use std::num::ParseIntError;

#[derive(Debug)]
enum MiError {
    Numero(ParseIntError),
    Vacio,
}

fn leer(s: &str) -> Result<i32, MiError> {
    if s.is_empty() {
        return Err(MiError::Vacio);
    }
    s.parse().map_err(MiError::Numero)
}
```

Cada variante es un modo de falla nombrado. Quien llama puede hacer `match` y actuar
distinto según el caso, que es justo lo que `Box<dyn Error>` no permite.

## `From` es lo que hace funcionar al `?`

```rust
use std::num::ParseIntError;
#[derive(Debug)] enum MiError { Numero(ParseIntError), Vacio }

impl From<ParseIntError> for MiError {
    fn from(e: ParseIntError) -> Self {
        MiError::Numero(e)
    }
}

fn leer(s: &str) -> Result<i32, MiError> {
    if s.is_empty() {
        return Err(MiError::Vacio);
    }
    Ok(s.parse()?)   // `?` aplica From: ParseIntError -> MiError
}
```

<div class="important-note">

Con el `impl From` en su lugar, el `map_err` de la diapositiva anterior sobra. Ese es
el mecanismo completo del `?`: extrae, **convierte** y retorna.

</div>

## Las dos librerías, y la regla

<div class="text-sm cp-table-compact">

| | `thiserror` | `anyhow` |
| :--- | :--- | :--- |
| Qué hace | genera el enum, el `Display` y los `From` | un tipo de error único que acepta cualquier cosa |
| Deja distinguir el fallo | sí | no |
| Pensada para | **librerías** | **binarios** |

</div>

<div class="important-note">

Regla práctica: una librería define su propio tipo de error, porque quien la use
necesita decidir qué hacer con cada caso. Un binario casi siempre solo tiene que
reportar y salir, así que `anyhow::Result<T>` alcanza.

</div>
