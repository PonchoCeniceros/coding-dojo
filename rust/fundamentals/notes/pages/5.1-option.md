# 5.1 · Option

## El problema: ausencia de valor

Muchos lenguajes usan `null` para representar "no hay valor". Rust no tiene `null`: el problema se resuelve con un enum de la librería estándar.

```rust
enum Option<T> {
    Some(T),
    None,
}
```

<div class="important-note">

`Option<T>` no es un caso especial del lenguaje: es un enum como cualquier otro. Forma parte del preludio, así que no requiere importarlo.

</div>

## Usar Option

```rust
fn buscar(nums: &[i32], objetivo: i32) -> Option<usize> {
    for (i, &n) in nums.iter().enumerate() {
        if n == objetivo {
            return Some(i);
        }
    }
    None
}

fn main() {
    match buscar(&[3, 7, 1], 7) {
        Some(i) => println!("encontrado en {i}"),
        None => println!("no encontrado"),
    }
}
```

* `Some(i)` envuelve el valor cuando existe; `None` marca su ausencia.
* El compilador obliga a manejar ambos casos. A diferencia de `null`, no existe la posibilidad de omitir la comprobación y fallar en ejecución.

## `if let` y `while let` sobre Option

Cuando solo interesa un caso (habitualmente `Some`), `match` resulta más verboso de lo necesario. `if let` y `while let` cubren ese caso:

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left">
  <div>

```rust
let dato: Option<i32> = Some(5);

if let Some(v) = dato {
    println!("hay un valor: {v}");
}
```

  </div>

<div>

```rust
let mut pila = vec![1, 2, 3];

// pop() devuelve Option<i32>: el bucle
// se detiene cuando da None
while let Some(v) = pila.pop() {
    println!("{v}"); // 3, 2, 1
}
```

</div>

</div>

## Combinadores comunes

<div class="important-note">

* **`.unwrap()`**: extrae el valor de `Some`, o provoca *panic* si es `None`. Solo conviene cuando la presencia del valor está garantizada.
* **`.is_some()` / `.is_none()`**: preguntan por el caso sin extraer el valor.
* **`.map(f)`**: transforma el valor interno si existe, sin tener que escribir un `match` manualmente.
* **`.take()`**: extrae el valor y deja `None` en su lugar.

</div>

```rust
let a: Option<i32> = Some(3);

let b = a.map(|v| v * 2); // Some(6)
let c = a.unwrap_or(0);   // 3 (o 0 si a fuera None)
```

## Dónde reaparece este patrón

El patrón `Option<Box<Nodo>>` de la siguiente sección (Listas enlazadas, Árboles) es este mismo: un enum de dos variantes sobre el que se hace *pattern matching* para decidir si seguir recorriendo la estructura o detenerse. `Option::take()` es el combinador descrito arriba.

## Hacer *match* sin mover el valor

Con `match opt`, el patrón `Some(s)` mueve el `String` fuera de `opt` y la última
línea deja de compilar (*E0382*). La solución es examinar una referencia.

```rust
fn main() {
    let opt: Option<String> = Some(String::from("hola"));

    match &opt {                            // examina &Option<String>
        Some(s) => println!("{} letras", s.len()),  // s: &String
        None    => println!("vacío"),
    }
    println!("{opt:?}");   // opt sigue viva: nada salió de ella
}
```

<div class="important-note">

El patrón `Some(s)` describe un `Option`, no una referencia a uno. Las formas no
coinciden y compila igual: el compilador atraviesa el `&` por su cuenta. Antes de
2018 se escribía a mano, `&Some(ref s)`.

</div>

## El modo de ligado

*Match ergonomics* es el nombre de esa regla. Cuando el valor examinado es una
referencia y el patrón no la menciona, el compilador la atraviesa y liga los nombres
como referencias del mismo tipo de préstamo.

<div class="important-note">

| Valor examinado | Patrón | Qué liga `s` |
| :--- | :--- | :--- |
| `Option<String>` | `Some(s)` | `String`, movido fuera del `Option` |
| `&Option<String>` | `Some(s)` | `&String` |
| `&mut Option<String>` | `Some(s)` | `&mut String` |

</div>

El patrón se escribe una sola vez y el modo lo decide el valor. Por eso
`if let Some(nodo) = &arbol` recorre una estructura sin consumirla (6.2 Rc, RefCell
y árboles).
