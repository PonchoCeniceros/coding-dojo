# 8.1 · Hilos

---
layout: center
---

## Lanzar un hilo

`thread::spawn` recibe un closure y lo ejecuta en un hilo del sistema operativo.
Devuelve un `JoinHandle` con el que se espera su resultado.

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        println!("el hilo trabaja");
        42
    });

    println!("main sigue por su cuenta");

    let resultado = handle.join().unwrap();
    println!("el hilo devolvió {resultado}");
}
```

`join()` bloquea hasta que el hilo termina y devuelve un `Result`: es `Err` si el
hilo entró en pánico.

## El closure necesita `move`

Un hilo puede sobrevivir a la función que lo lanzó, así que el compilador no acepta
que tome prestado nada del entorno.

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left">
  <div>
    <span class="text-xs cp-err font-bold block mb-1">Error: el closure presta</span>

```rust
use std::thread;

fn main() {
    let datos = vec![1, 2, 3];
    thread::spawn(|| {
        println!("{datos:?}");
    });
}
```

  </div>

  <div>
    <span class="text-xs cp-ok font-bold block mb-1">Válido: el closure posee</span>

```rust
use std::thread;

fn main() {
    let datos = vec![1, 2, 3];
    let h = thread::spawn(move || {
        println!("{datos:?}");
    });
    h.join().unwrap();
}
```

  </div>
</div>

<div class="important-note">

`error[E0373]: closure may outlive the current function`. Es el `move` de 4.3, ahora
obligatorio: el hilo se lleva los datos consigo.

</div>

## Nada garantiza el orden

```rust
use std::thread;

fn main() {
    let mut hilos = Vec::new();

    for i in 0..4 {
        hilos.push(thread::spawn(move || {
            println!("hilo {i}");
        }));
    }

    for h in hilos {
        h.join().unwrap();
    }
}
```

La salida cambia entre corridas. Si `main` termina sin hacer `join`, los hilos vivos
se cortan: el proceso no espera a nadie.
