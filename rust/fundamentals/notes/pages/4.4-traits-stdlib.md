## Los que aparecen todo el tiempo

<div class="text-sm cp-table-compact">

| Trait | Da acceso a | Se obtiene con |
| :--- | :--- | :--- |
| `Debug` | `{:?}` en `println!` | `#[derive(Debug)]` |
| `Display` | `{}` en `println!` | **solo a mano** |
| `Clone` | `.clone()` | `#[derive(Clone)]` |
| `Copy` | copia implícita en vez de move | `#[derive(Copy, Clone)]` |
| `Default` | `T::default()` | `#[derive(Default)]` |
| `PartialEq` / `Eq` | `==` y `!=` | `#[derive(PartialEq, Eq)]` |
| `PartialOrd` / `Ord` | `<`, `sort()`, `BinaryHeap` (5.5 Otras colecciones) | `#[derive(PartialOrd, Ord)]` |
| `Hash` | ser llave de un `HashMap` | `#[derive(Hash)]` |
| `From` / `Into` | conversión, y el `?` de 5.2 | a mano |
| `Drop` | correr código al destruirse el valor | a mano |

</div>

## `Display` se escribe a mano

No hay `derive` porque el formato de cara al usuario es una decisión, no algo
deducible de los campos.

```rust
use std::fmt;

struct Punto { x: i32, y: i32 }

impl fmt::Display for Punto {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

fn main() {
    println!("{}", Punto { x: 1, y: 2 });   // (1, 2)
}
```

Es el trait que hace falta para que un error propio (7.4 Manejo de errores idiomático) se pueda imprimir.

## `From` da `Into` gratis

```rust
struct Celsius(f64);
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

fn main() {
    let f: Fahrenheit = Celsius(100.0).into();   // `into` sale del `From`
    println!("{}", f.0);                         // 212
}
```

<div class="important-note">

Implementar `From` alcanza: la stdlib deriva `Into` a partir de él. La regla es
implementar siempre `From`, nunca `Into`.

</div>

## `Copy` no se elige libremente

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
struct Punto { x: i32, y: i32 }

#[derive(Debug, Clone)]      // no puede ser Copy: String no lo es
struct Persona { nombre: String }
```

<div class="important-note">

`Copy` exige que **todos** los campos sean `Copy` y que el tipo no implemente `Drop`.
Es la regla exacta de 3.2, ahora del lado de quien define el tipo.

</div>

## `Default` y la sintaxis de actualización

```rust
#[derive(Debug, Default)]
struct Config {
    reintentos: u32,
    verboso: bool,
    nombre: String,
}

fn main() {
    let c = Config { reintentos: 3, ..Default::default() };
    // Config { reintentos: 3, verboso: false, nombre: "" }
    println!("{c:?}");
}
```

`..Default::default()` rellena el resto de los campos. Es el patrón habitual para
structs de configuración con muchos campos opcionales.

## `Drop`: código al morir el valor

Corre al destruirse un valor. No se llama a mano: lo invoca el compilador al
terminar el scope del dueño, y es quien cumple la regla 3 de 3.2 Ownership.

```rust
struct Recurso(&'static str);

impl Drop for Recurso {
    fn drop(&mut self) { println!("suelto {}", self.0); }
}

fn main() {
    let _a = Recurso("a");
    let _b = Recurso("b");
}                       // imprime: suelto b · suelto a
```

<div class="important-note">

El orden es inverso al de declaración: el último en nacer es el primero en morir. De
ahí salen los *guards* de 6.2. Un tipo con `Drop` no puede ser `Copy`.

</div>

## No todo trait se puede implementar

La **regla del huérfano**: un `impl` solo se permite si el trait o el tipo son
propios. `Display` para `Vec<i32>` es *E0117: only traits defined in the current
crate can be implemented for types defined outside of the crate*.

```rust
struct Lista(Vec<i32>);        // newtype: tupla struct de un campo

impl fmt::Display for Lista {  // el tipo ya es propio: el impl se permite
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.len())
    }
}
```

<div class="important-note">

La salida es el patrón **newtype**: envolver el tipo ajeno en uno propio. Cuesta
cero en ejecución, y `Deref` (4.5 Operadores) devuelve los métodos del envuelto.

</div>
