# 3.3 · Borrowing

---
layout: center
---

1. Para flexibilizar el sistema de *ownership*, Rust admite una **excepción regulada**: el préstamo. Quien la vigila es el ***borrow checker***. Este sistema establece reglas sobre cómo el programa puede acceder a los datos, especialmente cuando varias partes necesitan leer o modificar la misma información.

2. Esto previene errores complejos (*bugs*) cuando diferentes secciones del programa intentan manipular los mismos datos de forma simultánea.

---
layout: center
---

## Referencias

En Rust, una **referencia** (`&`) es un puntero que permite acceder a un dato sin tomar su propiedad (*ownership*). 

* **Préstamo:** El dueño original conserva el control del dato; solo le da un permiso temporal a otra variable.
* **Sintaxis:** Se utiliza el operador `&` para crear una referencia de lectura, y `&mut` para una referencia que permita modificar el dato.

---
layout: center
---

## Reglas del **borrow checker**

Para asegurar que estos préstamos temporales no corrompan la memoria ni causen problemas al compilar, el *borrow checker* vigila estrictamente dos condiciones:

<div class="important-note">

1. Para un instante de tiempo dado, está permitida una y sólo una referencia mutable ó cualquier cantidad de referencias inmutables.
2. Toda referencia debe ser siempre válida.

</div>

---

```rust
fn main() {

    let r1 = &x;
    let r2 = &mut x;
    println!("{r1}");
}
```

  </div>

<br/>

> Se admiten tantas referencias de lectura como se quiera. Al crear una referencia mutable (`&mut`), ninguna otra referencia puede acceder al dato al mismo tiempo.

## `mut` es del binding, no del tipo

`mut` no forma parte del tipo. Describe qué se permite hacer con **ese** nombre.
Al mover el valor a otro binding, la mutabilidad se decide de nuevo.

```rust
fn main() {
    let a = String::from("hola");  // binding inmutable
    let mut b = a;      // se mueve a un binding mutable
    b.push('!');                   // válido: decide el binding nuevo
}
```

<div class="important-note">

No existe un `String` "mutable" y otro "inmutable". Existe un valor al que un
binding concreto permite o no permite mutar. Al moverlo, la decisión se toma de nuevo.

</div>

layout: center
---

## `let mut x` y `&mut x` no son lo mismo

Es la confusión más común al empezar. Una declara quién es el dueño; la otra
presta el derecho a modificar.

<div class="text-sm cp-table-compact">

| Escrito | Qué declara | Quién puede modificar el valor |
| :--- | :--- | :--- |
| `let x` | binding inmutable | nadie |
| `let mut x` | binding mutable | el dueño |
| `&x` | referencia compartida | nadie mientras la referencia viva |
| `&mut x` | referencia exclusiva | quien la recibe (exige que `x` sea `mut`) |

</div>

layout: center

## Los dos `mut` en una misma función

```rust
fn sumar(acc: &mut i32, n: i32) {
    *acc += n;                  // el préstamo permite modificar
}

fn main() {
    let mut total = 0;          // el dueño permite modificar
    sumar(&mut total, 5);   // `total` debe ser `mut`
    println!("{total}");        // 5
}
```

layout: center
---

## Cuando los dos `mut` aparecen juntos

Una referencia también es un valor, así que su binding puede ser mutable a su vez.

```rust
fn main() {
    let mut a = 1;
    let mut b = 2;

    let mut r = &mut a;  // binding mutable de una referencia exclusiva
    *r += 10;            // modifica `a`
    r = &mut b;          // reapunta: requiere el `mut` de `let mut r`
    *r += 10;

    println!("{a} {b}"); // 11 12
}
```

<div class="important-note">

`*r += 10` modifica el dato prestado. `r = &mut b` cambia a qué apunta el binding.

</div>
