## Dos tipos para un solo texto

`String` es dueño de su contenido y vive en el heap. `&str` es un préstamo de texto
que alguien más posee. Es la distinción de 3.2 y 3.3 aplicada al texto.

```rust
fn main() {
    let prestado: &str = "hola";   // vive en el binario
    let propio: String = String::from("hola"); // dueño: vive en el heap
    let otra_vez: &str = &propio;              // préstamo de un String

    println!("{prestado} {propio} {otra_vez}");
}
```

Un `&String` se convierte a `&str` solo, así que las funciones se escriben pidiendo
`&str`: aceptan las dos cosas.

## No se puede indexar

```rust
fn main() {
    let s = String::from("hola");
    let c = s[0];   // no compila
}
```

<div class="important-note">

Un `String` es UTF-8, y un carácter ocupa de uno a cuatro bytes. `s[0]` no tendría
una respuesta única: ¿el primer byte o el primer carácter? Rust prefiere no elegir
por ti y quita la operación.

</div>

## `.len()` cuenta bytes

```rust
fn main() {
    let s = String::from("café");

    println!("{}", s.len());           // 5  ← bytes
    println!("{}", s.chars().count()); // 4  ← caracteres
}
```

La `é` ocupa dos bytes. Cualquier código que asuma un byte por letra se rompe con el
primer acento, que en español es de inmediato.

## Recorrer el texto

```rust
fn main() {
    let s = "año";

    for c in s.chars() {
        print!("[{c}]");           // [a][ñ][o]
    }
    println!();

    for (i, c) in s.char_indices() {
        print!("{i}:{c} ");        // 0:a 1:ñ 3:o
    }
}
```

* `.chars()` da caracteres · `.bytes()` da bytes · `.char_indices()` da la posición en bytes de cada carácter.
* Los tres son iteradores (5.6 Iteradores), así que encadenan con `.map()`, `.filter()` y compañía.
