# 5.6 · Iteradores

---
layout: center
---

## `Iterator` es un trait con un método

Un iterador no es un tipo del lenguaje: es cualquier tipo que implemente el trait
`Iterator`. El trait obliga a una sola cosa, y declara el tipo de los elementos como
tipo asociado (4.2 Generics).

```rust
// std::iter::Iterator, reducido a lo obligatorio
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}
```

<div class="important-note">

`next` devuelve `Some` mientras queden elementos y `None` al agotarse. Pide
`&mut self` porque avanzar cambia el estado del iterador. Los demás métodos del
trait (`map`, `filter`, `take`, `fold`) son por default (4.1 Traits).

</div>

---
layout: center
---

## `next` a mano

Los adaptadores y los consumidores llaman a `next` por debajo. Llamarlo
directamente muestra lo único que hace un iterador: entregar el siguiente elemento
y avanzar.

```rust
fn main() {
    let v = vec![10, 20];
    let mut it = v.iter();           // it: Iter<'_, i32>, con Item = &i32

    assert_eq!(it.next(), Some(&10));
    assert_eq!(it.next(), Some(&20));
    assert_eq!(it.next(), None);     // agotado, y así se queda
    println!("agotado");
}
```

## Tres formas de iterar

La forma de recorrer un `Vec` determina qué ocurre con sus elementos. Es la
distinción entre propiedad (3.2 Ownership) y préstamo (3.3 Borrowing) aplicada a colecciones.

<div class="important-note">

| Método | Entrega cada elemento como | Efecto sobre la colección | En un `for` |
| :--- | :--- | :--- | :--- |
| `.iter()` | `&T` | intacta; solo lectura | `for x in &v` |
| `.iter_mut()` | `&mut T` | intacta; elementos modificables en su lugar | `for x in &mut v` |
| `.into_iter()` | `T` | consumida; deja de existir | `for x in v` |

</div>

layout: center

## `for` es azúcar sobre `IntoIterator`

Un `for` no recorre colecciones: pide un iterador y lo agota. Lo hace
`IntoIterator`, que `Vec` implementa tres veces, una por fila de la tabla anterior.

```rust
let v = vec![1, 2, 3];

for x in &v {                                // x: &i32
    println!("{x}");
}

// expansión aproximada
let mut it = IntoIterator::into_iter(&v);    // it = v.iter()
while let Some(x) = it.next() {
    println!("{x}");
}
```

<div class="important-note">

El `&` de la expresión decide cuál de las tres implementaciones se usa, y con ella
si el vector se consume.

</div>

## `.iter()` en la práctica

```rust
let v = vec![1, 2, 3];

for x in v.iter() {      // x: &i32
    println!("{x}");
}
// v sigue disponible aquí
```

## Adaptadores perezosos

Un adaptador transforma un iterador en otro. No recorre nada: describe la operación
y la difiere.

```rust
let v = vec![1, 2, 3, 4];

let pares = v.iter().filter(|&&n| n % 2 == 0);
let dobles = v.iter().map(|n| n * 2);
```

* `.filter(pred)` conserva los elementos que cumplen el predicado.
* `.map(f)` aplica `f` a cada elemento.

<div class="important-note">

Ninguna de las dos líneas recorre el vector. Un iterador es **perezoso**: la
descripción se ejecuta cuando un consumidor la solicita.

</div>

---
layout: center
---

## El doble `&` del predicado

`|&&n| n % 2 == 0` recibe dos capas de referencia. Es consecuencia de dos préstamos
encadenados:

<div class="important-note">

1. `v.iter()` sobre un `Vec<i32>` produce `&i32`.
2. `filter` presta ese elemento a su predicado, que lo recibe como `&&i32`.
3. El patrón `&&n` desestructura ambas capas y liga `n: i32`.

</div>

Forma equivalente sin patrón: `.filter(|n| **n % 2 == 0)`.

Los closures y los traits `Fn`, `FnMut` y `FnOnce` se tratan en 4.3.

## Consumidores

Un consumidor recorre el iterador y produce un valor final. Es lo que dispara la
ejecución.

```rust
let v = vec![1, 2, 3, 4];

let total: i32 = v.iter().sum();   // 10
let cuantos = v.iter().count();    // 4

let dobles: Vec<i32> = v.iter()
    .map(|n| n * 2)
    .collect();                    // [2, 4, 6, 8]
```

* `.sum()` y `.count()` reducen el iterador a un solo valor.
* `.collect()` reúne los elementos en una colección.

## Encadenar adaptadores

El uso habitual encadena adaptadores y cierra con un consumidor. Nada se ejecuta
hasta el `.collect()` final.

```rust
let v = vec![1, 2, 3, 4, 5, 6];

let resultado: Vec<i32> = v.iter()
    .filter(|&&n| n % 2 == 0) // pares:     2, 4, 6
    .map(|n| n * 10)          // por diez:  20, 40, 60
    .collect();               // en un Vec: [20, 40, 60]
```

<div class="important-note">

**Turbofish.** Cuando el compilador no puede deducir el tipo de destino, se anota en
el método: `.collect::<Vec<i32>>()`. Equivale al `: Vec<i32>` de la variable.

</div>
