# 3.5 · impl y métodos

---
layout: center
---

## `impl`: funciones asociadas y métodos

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left">
  <div>

```rust
struct Punto { x: f64, y: f64 }

impl Punto {
    // función asociada: sin self
    fn origen() -> Self {
        Self { x: 0.0, y: 0.0 }
    }

    // método: recibe &self
    fn distancia(&self, otro: &Punto) -> f64 {
        ((self.x - otro.x).powi(2)
            + (self.y - otro.y).powi(2)).sqrt()
    }
}
```

  </div>

<div class="text-sm space-y-3">

* `Self` es un alias del tipo que implementa el bloque.
* Una función asociada no recibe `self` y se invoca con `Punto::origen()`.
* Un método recibe `self` y se invoca sobre una instancia.

</div>

</div>

---
layout: center
---

## Las tres formas de recibir `self`

<div class="text-sm cp-table-compact">

| Firma | Qué hace con la instancia | Equivale a |
| :--- | :--- | :--- |
| `&self` | la presta para leer | `&Punto` |
| `&mut self` | la presta para modificar | `&mut Punto` |
| `self` | la consume | `Punto` por valor |

</div>

Las funciones asociadas sin `self` suelen ser constructores, y por convención se
llaman `new`.

## Un método es azúcar sintáctico sobre un préstamo

Cuando se llama a un método con `caja.metodo(...)`, Rust no hace nada mágico: por debajo, toma el préstamo que `self` pide y lo pasa como primer argumento a la función asociada.

<div class="grid grid-cols-2 gap-x-6 mt-2 w-full text-left text-sm cp-code-compact">
  <div>

```rust
struct Caja {
    valor: i32,
}

impl Caja {
    fn ver(&self) -> &i32 {
        &self.valor
    }

    fn cambiar(&mut self, n: i32) {
        self.valor = n;
    }
}
```

  </div>

<div class="space-y-4">

```rust
let mut caja = Caja { valor: 5 };

caja.ver();
// == Caja::ver(&caja)

caja.cambiar(10);
// == Caja::cambiar(&mut caja, 10)
```

</div>

</div>

## El método no inventa nada

<div class="important-note">

`&self` y `&mut self` no son un mecanismo aparte del *borrowing*: son el mismo `&` y
`&mut`, tomados automáticamente sobre la instancia.

De ahí que las reglas del borrow checker apliquen igual a las llamadas de métodos,
que es lo que muestra la diapositiva siguiente.

</div>

---
layout: center
---

## Las reglas de borrowing también aplican a métodos

Como `caja.ver()` es `Caja::ver(&caja)` y `caja.cambiar(10)` es `Caja::cambiar(&mut caja, 10)`, la regla anterior (*una mutable o varias inmutables, nunca ambas al mismo tiempo*) se cumple igual entre llamadas a métodos:

<div class="grid grid-cols-2 gap-y-6 gap-x-8 items-center mt-4 w-full text-left">

  <div class="[&_pre]:my-0">
    <span class="text-xs cp-ok font-bold block mb-1">Válido: dos préstamos de solo lectura</span>

```rust
fn main() {
    let caja = Caja { valor: 5 };
    let a = caja.ver();
    let b = caja.ver();
    println!("{a} y {b}");
}
```

  </div>

  <div class="[&_pre]:my-0">
    <span class="text-xs cp-err font-bold block mb-1">Error: préstamo vivo + método mutable</span>

```rust
fn main() {
    let mut caja = Caja { valor: 5 };
    let v = caja.ver();     // &self activo
    caja.cambiar(10);   // &mut self: choca
    println!("{v}");
}
```

  </div>

</div>

<br/>

> `caja.ver()` solo lee, y admite tantas llamadas como se quiera. Mientras su resultado siga en uso, `caja.cambiar(10)` pide un `&mut self` que no puede coexistir con ese préstamo de lectura.
