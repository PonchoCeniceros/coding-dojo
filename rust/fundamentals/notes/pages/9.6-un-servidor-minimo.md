# 9.6 · Un servidor mínimo

---
layout: center

## Qué vamos a montar

Una API REST con un solo endpoint, `GET /`, que devuelve JSON y lleva la cuenta de
cuántas veces la llamaron. El contador vive en memoria y lo comparten todas las
peticiones, que es lo que obliga a usar lo de la sección 8.

<div class="text-sm cp-table-compact">

| Pieza | Crate | Papel |
| :--- | :--- | :--- |
| el runtime | `tokio` | ejecuta los futuros (9.3 El runtime) |
| el servidor y el ruteo | `axum` | recibe peticiones y llama al handler |
| el JSON | `serde_json` | serializa la respuesta |

</div>

`axum` lo mantiene el equipo de tokio y se apoya en `hyper` para hablar HTTP y en
`tower` para el middleware. Su idea propia son los *extractores*: el tipo de cada
parámetro del handler declara qué se saca de la petición.

## Un servidor mínimo

El pago de las secciones 8 y 9. Compila, corre y responde JSON en el puerto 3000.

```rust
use std::sync::{Arc, Mutex};
use axum::{extract::State, routing::get, Json, Router};

#[derive(Clone)]
struct Estado { visitas: Arc<Mutex<u64>> }

async fn saludo(State(e): State<Estado>) -> Json<serde_json::Value> {
    let n = { let mut v = e.visitas.lock().unwrap(); *v += 1; *v };
    Json(serde_json::json!({ "visitas": n }))
}

#[tokio::main]
async fn main() {
    let estado = Estado { visitas: Arc::new(Mutex::new(0)) };
    let app = Router::new().route("/", get(saludo)).with_state(estado);
    let l = tokio::net::TcpListener::bind("0.0.0.0:3000").await.unwrap();
    axum::serve(l, app).await.unwrap();
}
```

## De dónde sale cada línea

Ninguna línea usa un concepto ajeno al cuaderno. Lo nuevo es solo el crate.

<div class="text-sm cp-table-compact">

| En el código | Explicado en |
| :--- | :--- |
| `Arc<Mutex<u64>>` como estado | 8.3 Estado compartido |
| `#[derive(Clone)]` sobre el estado | 4.4 Traits de la stdlib |
| `async fn saludo` | 9.2 async, await y Future |
| el `lock()` dentro de un bloque propio | 9.4 Send en las tareas |
| `#[tokio::main]` | 9.3 El runtime |
| `.await.unwrap()` | 5.2 Result |

</div>

<div class="important-note">

`axum` es un crate externo. Esto es la versión 0.8, y su API cambia entre versiones
menores: en 0.6 y 0.7 el arranque del servidor se escribía distinto.

</div>

## El error que vas a ver

Con el `lock()` fuera del bloque, esto es lo que reporta axum:

```text
error[E0277]: the trait bound `fn(State<Estado>) -> impl Future
  <Output = Json<Value>> {saludo}: Handler<_, _>` is not satisfied
   --> src/main.rs:26:25
    |
 26 |         .route("/", get(saludo))
    |                     --- ^^^^^^ the trait `Handler<_, _>` is
    |                                not implemented for fn item
    |
    = note: Consider using `#[axum::debug_handler]` to improve the
            error message
```

<div class="important-note">

No menciona `Send`, ni el `MutexGuard`, ni el `.await`, y señala una línea sin
falla. Es lo de 9.4: el guard cruzó el `.await`, el futuro dejó de ser `Send` y la
función dejó de cumplir `Handler`. `#[axum::debug_handler]` lo traduce.

</div>
