# 6.3 · Despacho dinámico

---
layout: center
---

## Dos formas de usar un trait

Un trait se puede resolver en compilación o en ejecución. La diferencia decide si el
tipo concreto se conoce al compilar o hasta que el programa corre.

<div class="text-sm cp-table-compact">

| | Genérico / `impl Trait` | `dyn Trait` |
| :--- | :--- | :--- |
| Se resuelve | al compilar (*monomorfización*) | al ejecutar (tabla de métodos) |
| Costo en ejecución | ninguno | una indirección por llamada |
| Costo en compilación | una copia del código por tipo | una sola copia |
| Tipos por colección | uno solo | varios distintos |

</div>

---
layout: center
---

## Estático: el compilador conoce el tipo

```rust
trait Figura {
    fn area(&self) -> f64;
}

struct Circulo(f64);
struct Cuadrado(f64);

impl Figura for Circulo {
    fn area(&self) -> f64 { 3.14 * self.0 * self.0 }
}

impl Figura for Cuadrado {
    fn area(&self) -> f64 { self.0 * self.0 }
}

fn imprimir(f: &impl Figura) {
    println!("{:.2}", f.area());
}
```

El compilador genera una versión de `imprimir` para `Circulo` y otra para `Cuadrado`.
La llamada es directa, como si estuviera escrita a mano.

layout: center

## Dinámico: el tipo se sabe al ejecutar

```rust
fn main() {
    let figuras: Vec<Box<dyn Figura>> = vec![
        Box::new(Circulo(1.0)),
        Box::new(Cuadrado(2.0)),
    ];

    for f in &figuras {
        println!("{:.2}", f.area());
    }
}
```

<div class="important-note">

Un `Vec<T>` exige que todos sus elementos sean del mismo tipo. `Box<dyn Figura>` lo
consigue: el tipo del elemento es siempre el mismo puntero, y lo que cambia es a
dónde apunta.

</div>

layout: center

## Por qué hace falta el `Box`

`dyn Figura` no tiene tamaño conocido en compilación: un `Circulo` y un `Cuadrado`
ocupan distinto. Por eso `dyn Trait` siempre se usa detrás de un puntero, igual que
`str` (3.4 Strings).

<div class="text-sm cp-table-compact">

| Escrito | Qué es |
| :--- | :--- |
| `Box<dyn Figura>` | dueño en el heap, la forma habitual |
| `&dyn Figura` | préstamo, cuando no hace falta poseerlo |
| `Rc<dyn Figura>` | compartido entre varios dueños (6.2 Rc, RefCell y árboles) |

</div>

layout: center
---

## Las dos formas no son excluyentes

`Figura` se usó de las dos maneras en esta misma sección: por genérico en
`imprimir(&impl Figura)` y por tabla en `Vec<Box<dyn Figura>>`. El trait se declara
una vez y cada punto de uso elige cómo resolverlo.

<div class="important-note">

La asimetría está del otro lado: todo trait sirve como bound genérico, pero solo los
*dyn compatibles* sirven como `dyn Trait`. Un trait es dyn compatible si sus métodos
se pueden llamar conociendo solo el puntero y la tabla.

</div>

Por eso `Iterator` admite `Box<dyn Iterator<Item = u64>>` y `Clone` no admite
`Box<dyn Clone>`: `clone` devuelve `Self`.

## Qué impide ser `dyn`

<div class="text-sm cp-table-compact">

| En el trait | Por qué rompe la tabla |
| :--- | :--- |
| método genérico, `fn f<T>(&self, x: T)` | haría falta una entrada por cada `T` posible |
| método que devuelve `Self` | el tamaño del retorno se desconoce |
| función asociada sin `self` | no hay objeto del que sacar la tabla |
| `Self: Sized` como bound del trait | declara que el tipo se conoce al compilar |

</div>

```rust
trait Dibujable {
    fn dibujar(&self);
    fn copia(&self) -> Self where Self: Sized;   // excluido de la tabla
}
```

Marcar el método con `where Self: Sized` lo deja fuera de la tabla y solo disponible
por genérico. El resto del trait sigue sirviendo como `dyn`. Sin esa marca, el error
es *E0038: the trait is not dyn compatible*.

layout: center

## Cuál usar

<div class="important-note">

**Genérico por default.** Es lo más rápido y lo que permite más comprobaciones en
compilación.

**`dyn` cuando el conjunto de tipos se decide en ejecución**, o cuando la
monomorfización haría crecer demasiado el binario. El caso típico es una colección
heterogénea. La decisión es por punto de uso, no por trait.

</div>
