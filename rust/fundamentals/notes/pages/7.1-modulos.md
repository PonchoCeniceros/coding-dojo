# 7.1 · Módulos

---
layout: center
---

## El problema: todo en un archivo

1. Un trial de LeetCode cabe en un archivo: un `struct Solution`, sus métodos y los tests al final.
2. Un proyecto real no. Hacen falta límites que separen responsabilidades, y una forma de decidir **qué es visible desde afuera y qué queda oculto**.
3. Los **módulos** son ese mecanismo: organizan el código en un árbol de espacios de nombres y controlan la visibilidad.

<div class="important-note">

Los módulos no son archivos: son **una jerarquía lógica**. Suelen coincidir con archivos porque resulta cómodo, pero un módulo puede vivir dentro de otro archivo, y un archivo puede contener varios módulos.

</div>

---
layout: center
---

## `mod`: declarar un módulo

Un módulo se declara con `mod`. Definido en línea, delimita un ámbito dentro del mismo archivo:

```rust
mod geometria {
    pub struct Punto {
        pub x: f64,
        pub y: f64,
    }

    pub fn origen() -> Punto {
        Punto { x: 0.0, y: 0.0 }
    }
}

fn main() {
    let p = geometria::origen();
}
```

* `geometria::origen()` — la ruta usa `::` para descender en el árbol de módulos.

## Un módulo por archivo

Cuando `mod` no lleva cuerpo, el compilador **busca el código en un archivo con ese nombre**:

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left">
  <div>

```rust
// src/main.rs
mod geometria;   // busca geometria.rs

fn main() {
    let p = geometria::origen();
}
```

  </div>

<div>

```rust
// src/geometria.rs
pub struct Punto {
    pub x: f64,
    pub y: f64,
}

pub fn origen() -> Punto {
    Punto { x: 0.0, y: 0.0 }
}
```

</div>

</div>

<div class="important-note">

El archivo **no se incluye solo**: sin la línea `mod geometria;`, `geometria.rs`
queda fuera de la compilación. La declaración es lo que lo integra al árbol.

</div>

## Visibilidad: privado por default

Todo es **privado por default**. `pub` abre un nivel, y hay que abrirlos todos en el camino:

```rust
mod api {
    pub mod rutas {              // sin pub, invisible desde afuera
        pub fn salud() -> u8 { 200 }
        fn interna() {}          // solo visible dentro de `rutas`
    }
}

fn main() {
    api::rutas::salud();         // necesita pub en `rutas` Y en `salud`
}
```

<div class="important-note">

Un hijo ve lo privado de sus ancestros; un padre **no** ve lo privado de sus hijos.

</div>

## Módulos anidados en carpetas

Cuando un módulo tiene submódulos, se convierte en carpeta. El archivo que representa al módulo padre puede ser `nombre.rs` junto a la carpeta, o `nombre/mod.rs` dentro de ella:

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left text-sm">
  <div>

```text
src/
├── main.rs          mod api;
├── api.rs           pub mod rutas;
└── api/
    └── rutas.rs     pub fn salud() {}
```

  </div>

<div>

```text
src/
├── main.rs          mod api;
└── api/
    ├── mod.rs       pub mod rutas;
    └── rutas.rs     pub fn salud() {}
```

</div>

</div>

<br/>

> Ambas formas son equivalentes. La primera (`api.rs` + `api/`) es la convención moderna; la segunda (`api/mod.rs`) es la histórica y aún se ve mucho en código existente.

## `use`: acortar rutas

Escribir la ruta completa cada vez es tedioso. `use` trae un nombre al ámbito actual:

<div class="grid grid-cols-2 gap-x-6 mt-4 w-full text-left">
  <div>

```rust
// sin use
fn main() {
    let p = api::rutas::salud();
}

// con use
use api::rutas::salud;

fn main() {
    let p = salud();
}
```

  </div>

<div>

```rust
// varios de una vez
use std::collections::{HashMap, HashSet};

// renombrar al importar
use std::io::Result as IoResult;

// todo lo público (evitar
// fuera de preludios y tests)
use api::rutas::*;
```

</div>

</div>

## Rutas: `crate`, `super`, `self`

<div class="text-sm cp-table-compact">

| Prefijo | Desde dónde parte | Ejemplo |
| :--- | :--- | :--- |
| `crate::` | la raíz del crate actual (ruta absoluta) | `use crate::api::rutas;` |
| `super::` | el módulo padre | `use super::Punto;` |
| `self::` | el módulo actual | `use self::interna;` |
| *(nombre)* | un crate externo o de la stdlib | `use std::collections::HashMap;` |

</div>

<div class="important-note">

`use katas::s;` en los trials es este mismo mecanismo: `katas` es el nombre del crate, y `s` un macro exportado en su raíz. La misma sintaxis sirve para módulos propios y para dependencias externas.

</div>
