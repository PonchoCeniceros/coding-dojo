## Lo que `unsafe` no apaga

No desactiva las reglas de esta sección. Dos `&mut` dentro de un bloque `unsafe`
siguen siendo *E0499*, y encima el compilador avisa *unnecessary `unsafe` block*.

<div class="text-sm cp-table-compact">

| Lo único que habilita | Ejemplo |
| :--- | :--- |
| desreferenciar un puntero crudo | `*p` con `p: *const i32` |
| llamar a una función `unsafe` | interfaces con C |
| leer o escribir un `static mut` | estado global mutable |
| implementar un trait `unsafe` | `Send` y `Sync` a mano |

</div>

<div class="important-note">

Un bloque `unsafe` es una promesa del programador, no una excepción del compilador:
declara que ahí se cumplen a mano invariantes que ya no puede verificar. Por eso un
error de memoria se busca primero en esos bloques.

## Cómo leer un error del compilador

Cada error de memoria trae un código `E0xxx`. Casi todos los de esta sección son
uno de tres casos: un valor movido y vuelto a usar, préstamos que no pueden convivir,
o una referencia que sobrevive a su dueño.

<div class="important-note">

La pregunta útil no es *"¿cómo callo al compilador?"* sino *"¿qué regla violé?"*.
Las siguientes diapositivas son el catálogo mínimo.

</div>

## `E0382` · valor movido

```rust
fn main() {
    let s = String::from("hola");
    let t = s;          // `s` se mueve a `t`
    println!("{s}");    // E0382: borrow of moved value
}
```

* **Regla violada**: cada valor tiene un solo dueño (3.2 Ownership).
* **Arreglo**: `let t = s.clone();` si hacen falta dos valores, o `let t = &s;` si solo hace falta leer.

## `E0499` y `E0502` · préstamos incompatibles

<div class="text-sm cp-table-compact">

| Código | Qué se intentó | Regla violada |
| :--- | :--- | :--- |
| `E0499` | dos `&mut` sobre el mismo dato a la vez | solo puede existir una referencia exclusiva |
| `E0502` | mutar mientras vive un `&` | una exclusiva **o** varias compartidas, nunca ambas |

```rust
fn main() {
    let mut s = String::from("hola");
    let r = &s;         // préstamo compartido
    s.push('!');        // E0502: necesita &mut, y `r` sigue vivo
    println!("{r}");
}
```

## `E0597` · la referencia vive más que el dato

```rust
fn main() {
    let r;
    {
        let x = 5;
        r = &x;         // E0597: `x` does not live long enough
    }                   // aquí muere `x`
    println!("{r}");    // ...y `r` seguiría apuntando ahí
}
```

* **Regla violada**: toda referencia debe ser válida durante todo su lifetime (3.5 impl y métodos).
* **Arreglo**: sacar el dato al alcance exterior, o quedarse con una copia en vez de una referencia.

## `E0106` · falta el lifetime

```rust
struct Envoltura {
    texto: &str,        // E0106: missing lifetime specifier
}
```

Una struct que guarda una referencia necesita declarar cuánto vive esa referencia,
porque el compilador no puede deducirlo solo: `struct Envoltura<'a> { texto: &'a str }`.

<div class="important-note">

Es el error que empuja a la pregunta de diseño real: ¿esta struct **presta** el texto
o debería **poseerlo**? Cambiar `&str` por `String` también resuelve el error, y
muchas veces es la respuesta correcta.

</div>

## Los cinco de un vistazo

<div class="text-sm cp-table-compact">

| Código | Mensaje típico | Arreglo habitual |
| :--- | :--- | :--- |
| `E0382` | *borrow of moved value* | `.clone()`, o prestar en vez de mover |
| `E0499` | *cannot borrow more than once as mutable* | acortar el alcance del primer `&mut` |
| `E0502` | *cannot borrow as mutable ... also borrowed as immutable* | terminar de usar el `&` antes de mutar |
| `E0597` | *does not live long enough* | subir el dato de alcance |
| `E0106` | *missing lifetime specifier* | anotar `<'a>` o pasar a un tipo dueño |
