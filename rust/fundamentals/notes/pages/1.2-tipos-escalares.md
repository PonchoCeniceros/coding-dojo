## El desbordamiento no se ignora

Rust decide qué hacer al pasarse del máximo según el perfil de compilación, y las
dos decisiones son distintas.

```rust
fn main() {
    let mut n: i32 = i32::MAX;
    n += 1;
    println!("{n}");
}
```

<div class="important-note">

En **debug** el programa aborta: *thread 'main' panicked at: attempt to add with
overflow*. En **release** el valor da la vuelta y sale `-2147483648`. Mismo código,
mismo binario, comportamiento distinto según cómo se compiló.

</div>

Lo controla `overflow-checks`, activable en release desde `Cargo.toml`.

## Cuando el desbordamiento es parte del problema

Cuando dar la vuelta o toparse es lo correcto, se pide de forma explícita. Cada
operación aritmética tiene cuatro variantes, y ninguna depende del perfil.

```rust
fn main() {
    let n = i32::MAX;

    println!("{:?}", n.checked_add(1));      // None
    println!("{}",   n.wrapping_add(1));     // -2147483648
    println!("{}",   n.saturating_add(1));   // 2147483647
    println!("{:?}", n.overflowing_add(1));  // (-2147483648, true)
}
```

<div class="important-note">

`checked_` devuelve `Option` (5.1 Option) y es la que conviene por default cuando la
entrada no es de fiar. `saturating_` se topa en el límite. `wrapping_` da la vuelta a
propósito, como en un hash. Existen para `add`, `sub`, `mul`, `pow` y `neg`.

</div>

## Las dos deudas del deck

Dos cosas aparecen en los ejemplos antes de poder explicarse. No se pueden evitar sin
volver el código irreal, así que quedan declaradas aquí.

<div class="important-note">

* El texto entre comillas (`"hola"`) es un **`&str`**, y ese `&` significa *referencia*.
* Desde la sección 2 los ejemplos usan **`String`**, el texto que crece.

</div>

Basta con leerlas como "una cadena de texto". El `&` llega en 3.3, el heap donde vive
`String` en 3.1, y ambos tipos a fondo en 3.4.
