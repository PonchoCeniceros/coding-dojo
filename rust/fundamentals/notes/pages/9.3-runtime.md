# 9.3 · El runtime

---
layout: center
---

## El lenguaje trae la sintaxis, no el motor

Rust define `async`, `.await` y el trait `Future`. No incluye nada que los ejecute.
Alguien tiene que preguntarle a cada futuro si ya terminó, y ese *ejecutor* es un
crate externo.

<div class="text-sm cp-table-compact">

| Parte | De dónde viene |
| :--- | :--- |
| `async`, `.await`, `Future` | el lenguaje y la stdlib |
| ejecutor, temporizadores, IO asíncrono | un crate: `tokio`, `async-std`, `smol` |

</div>

Es una decisión de diseño: un runtime dentro del lenguaje sería peso muerto para
quien programa un microcontrolador.

---
layout: center
---

## `#[tokio::main]` no es magia

```rust
async fn trabajo() -> u32 { 42 }

#[tokio::main]
async fn main() {
    println!("{}", trabajo().await);
}
```

Ese atributo reescribe la función.

---
layout: center
---

## Lo que queda tras la expansión

```rust
async fn trabajo() -> u32 { 42 }

fn main() {
    tokio::runtime::Runtime::new()
        .unwrap()
        .block_on(async {
            println!("{}", trabajo().await);
        });
}
```

`main` no puede ser `async` de verdad: alguien tiene que crear el runtime antes de
que exista la primera tarea.

layout: center
---

## `block_on` y `spawn`

<div class="text-sm cp-table-compact">

| Llamada | Qué hace |
| :--- | :--- |
| `block_on(fut)` | bloquea **este** hilo hasta que el futuro termina; es el puente entre el mundo síncrono y el asíncrono |
| `tokio::spawn(fut)` | entrega el futuro al runtime como una tarea independiente y sigue de inmediato |

</div>

<div class="important-note">

`spawn` devuelve un `JoinHandle`, igual que `thread::spawn` (8.1 Hilos). La diferencia es
que una tarea no es un hilo: el runtime reparte miles de tareas sobre unos pocos
hilos.

</div>
