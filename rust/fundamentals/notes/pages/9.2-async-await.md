# 9.2 · async, await y Future

---
layout: center
---

## Una `async fn` no devuelve su resultado

Devuelve un `Future`: un valor que **describe** el cálculo y que todavía no ha
corrido.

```rust
async fn leer() -> u32 {
    42
}

// el tipo real es, aproximadamente:
// fn leer() -> impl Future<Output = u32>
```

<div class="important-note">

`Future` es un trait de la librería estándar (4.1 Traits), con un método `poll` que se
pregunta *"¿ya terminaste?"*. Nadie lo llama a mano.

</div>

---
layout: center
---

## Llamarla no ejecuta nada

```rust
async fn leer() -> u32 { 42 }

async fn total() -> u32 {
    let futuro = leer();     // no corre nada todavía
    let a = futuro.await;    // aquí sí
    let b = leer().await;
    a + b
}
```

<div class="important-note">

Es la misma pereza de los iteradores (5.6 Iteradores): el adaptador describe y el consumidor
ejecuta. Aquí `async` describe y `.await` consume. Un futuro que nunca se espera
nunca corre, y el compilador lo avisa con `unused_implementer of Future`.

</div>

## `.await` cede el control, no bloquea

```rust
async fn descargar(id: u32) -> String {
    format!("recurso {id}")
}

async fn dos() -> (String, String) {
    // mientras espera, el hilo atiende otras tareas
    let a = descargar(1).await;
    let b = descargar(2).await;
    (a, b)
}
```

* `.await` solo puede aparecer dentro de una `async fn` o de un bloque `async`.
* El código se lee secuencial y se ejecuta intercalado. Esa es toda la ganancia.
* Este ejemplo aún es secuencial: `b` empieza cuando `a` termina.

## Esperar dos cosas a la vez

```rust
async fn descargar(id: u32) -> String {
    format!("recurso {id}")
}

async fn dos() -> (String, String) {
    let fa = descargar(1);
    let fb = descargar(2);
    tokio::join!(fa, fb)      // ambos avanzan a la vez
}
```

<div class="important-note">

`join!` es del runtime, no del lenguaje. La concurrencia real aparece cuando varios
futuros avanzan juntos; poner `.await` uno tras otro es solo código secuencial
escrito de forma pausable.

</div>
