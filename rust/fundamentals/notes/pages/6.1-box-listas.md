# 6.1 · Box y listas enlazadas

---
layout: center
---

## El problema: tipos recursivos

1. Una lista enlazada es una secuencia de nodos donde cada nodo apunta al siguiente. La forma más directa de modelarlo sería:

```rust
struct Nodo {
    valor: i32,
    siguiente: Nodo,
}
```

2. Este código no compila. Rust necesita conocer el tamaño exacto de cada tipo en tiempo de compilación, pero `Nodo` contiene otro `Nodo`, que contiene otro `Nodo`... un tamaño infinito.

---
layout: center
---

## `Box<T>`: indirección al heap

`Box<T>` es un puntero inteligente que guarda un valor en el heap y deja en el stack solo un puntero de tamaño fijo hacia él.

```rust
struct Nodo {
    valor: i32,
    siguiente: Box<Nodo>,
}
```

<div class="important-note">

Al envolver el campo recursivo en un `Box`, el compilador ya no necesita conocer el tamaño de `Nodo` completo, solo el de un puntero.

</div>

Pero sigue faltando algo: ¿cómo se representa el final de la lista, donde no hay "siguiente" nodo?

---
layout: center
---

## Qué hace especial a `Box<T>`

`Box<T>` es un struct genérico de la stdlib, con un parámetro de tipo como los
de 4.2 Generics.
Lo distinto no es la genericidad: es lo que hace con `T`.

<div class="text-sm cp-table-compact">

| | Un struct genérico cualquiera | `Box<T>` |
| :--- | :--- | :--- |
| El parámetro `T` | igual | igual |
| Dónde vive el dato | donde viva el struct | siempre en el heap |
| Tamaño en el stack | depende de `T` | un puntero; dos si `T` no tiene tamaño |
| Al salir de scope | libera sus campos | libera además la memoria del heap |
| `T` sin tamaño conocido | no se admite | se admite: `Box<dyn Figura>` |

</div>

Sigue habiendo un solo dueño: el `Box`. Lo que cambia es dónde está el dato, cuánto
ocupa el dueño, y que `T` puede no tener tamaño conocido (6.3 Despacho dinámico).

---
layout: center
---

## `Box` uniformiza el tamaño, no el tipo

Cualquier `Box<T>` ocupa lo mismo, sin importar qué tan grande sea `T`:

<div class="text-sm cp-table-compact">

| Tipo | Bytes en el stack |
| :--- | ---: |
| `[u8; 1024]` | 1024 |
| `Box<[u8; 1024]>` | 8 |
| `Box<String>` | 8 |
| `Box<dyn Figura>` | 16: dato y tabla |

</div>

<div class="important-note">

El cajón uniforma el tamaño, no el tipo. `Box<u8>` y `Box<String>` son tipos
distintos: juntarlos en un `Vec` da *E0308, expected `u8`, found `String`*.

</div>

Uniformar el tipo es trabajo de `dyn` (6.3 Despacho dinámico): ahí `dyn` borra el
tipo concreto y `Box` le devuelve un tamaño.

layout: center

## `Option<Box<Nodo>>`: representar el final

La lista termina cuando un nodo no tiene siguiente. Esa ausencia se modela con `Option`, no con un valor especial como `null` (que Rust no tiene):

```rust
struct Nodo {
    valor: i32,
    siguiente: Option<Box<Nodo>>,
}

fn main() {
    let ultimo = Nodo { valor: 3, siguiente: None };
    let segundo = Nodo { valor: 2, siguiente: Some(Box::new(ultimo)) };
    let primero = Nodo { valor: 1, siguiente: Some(Box::new(segundo)) };
}
```

* `None` marca el final de la lista.
* `Some(Box::new(nodo))` envuelve el siguiente nodo, ya en el heap.

## Recorrer sin robar la propiedad

Para leer la lista sin consumirla, se recorre con una **referencia** que avanza nodo a nodo. Es el patrón de préstamo de la sección Borrowing y lifetimes:

```rust
fn imprimir(nodo: &Option<Box<Nodo>>) {
    let mut actual = nodo;
    while let Some(n) = actual {
        println!("{}", n.valor);
        actual = &n.siguiente;
    }
}
```

<br>

* `actual` es una referencia (`&Option<Box<Nodo>>`), no el dueño de los nodos.
* En cada vuelta, `actual` avanza al campo `siguiente` del nodo actual. El nodo nunca se mueve; solo cambia la referencia que lo señala.

## Por qué mover no es una opción

Para quitar un nodo de la lista hace falta poseerlo, no prestarlo. El intento
directo no compila:

```rust
fn quitar_primero(lista: &mut Option<Box<Nodo>>) -> Option<Box<Nodo>> {
    let primero = *lista;   // E0507: cannot move out of `*lista`
    primero                 //        which is behind a mutable reference
}
```

<div class="important-note">

`lista` es un préstamo, no el dueño (3.3 Borrowing). Sacar el valor dejaría al dueño
real con un hueco, y la regla 2 del borrow checker exige que la referencia siga
siendo válida hasta el final de su vida. El compilador lo rechaza al compilar.

</div>

---
layout: center
---

## `take()`: mover y reponer en un solo paso

La salida no es sacar el valor, sino intercambiarlo por otro válido. Eso es
`Option::take()`, que deja `None` donde estaba el valor:

```rust
// std::option::Option::take, en esencia
fn take(&mut self) -> Option<T> {
    std::mem::replace(self, None)
}
```

<div class="important-note">

En ningún instante hay un hueco: `replace` escribe `None` y devuelve lo que había.
El dueño detrás del préstamo siempre tiene un `Option` completo, así que las dos
reglas del borrow checker se cumplen sin necesidad de verificar nada en ejecución.

</div>

## Quitar el primer nodo

```rust
fn quitar_primero(lista: &mut Option<Box<Nodo>>) -> Option<Box<Nodo>> {
    match lista.take() {                       // la lista queda en None
        Some(mut primero) => {
            *lista = primero.siguiente.take();  // el resto, a su lugar
            Some(primero)
        }
        None => None,
    }
}
```

Dos `take()` encadenados, y el estado del dueño en cada punto:

* Al entrar: `lista` posee toda la cadena.
* Tras el primer `take()`: `lista` es `None`, y la cadena entera está en `primero`.
* Tras el segundo: `lista` posee la cola, y `primero` queda suelto con `siguiente: None`.
